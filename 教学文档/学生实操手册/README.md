# 《校园实验室预约与审批系统》实验教程使用说明

## 一、教程定位

本教程面向非计算机专业学生，以“校园实验室预约与审批系统”为贯穿项目，用 D00—D16 共 17 个开发检查点展示一个 Web 系统从空目录到 `dev-v1.0` 的形成过程。

本教程不要求学生凭空编写程序，也不使用“一键生成系统”的自动化平台。每一步所需的完整文件均由课程提供，学习者通过亲自复制、启动、操作、核对和测试，理解文件职责、功能变化与软件开发过程。

## 二、基本学习方法

每个检查点均按下列顺序完成：

```text
明确本步起点与终点
→ 停止上一步程序
→ 从配套资源复制或替换完整文件
→ 启动系统并完成指定操作
→ 对照真实截图核验页面结果
→ 运行自动测试
→ 在完成检查表中确认结果
```

除非实验步骤明确要求删除文件，否则不得自行清空个人项目。不要把若干步骤一次性全部覆盖；每完成一个 D 步骤，都要立即运行并确认本步独有的可见结果。

## 三、课前准备

首次上课前应完成[《实验准备：学生电脑基本开发环境搭建》](00_课前准备_学生电脑基本开发环境搭建.md)。该文档从普通 Windows 笔记本开始，依次完成 Python 3.11、Visual Studio Code、Git、课程资源目录、个人工作目录和项目虚拟环境的配置与验收。

课程统一使用两个目录：

```text
D:\campus-lab-course    课程资源目录，只用于复制和核对
D:\campus-lab-work      个人项目目录，全部实验操作在此进行
```

电脑没有 D 盘时，应在课前选定另一个可写的数据盘，并在全部实验中保持相同盘符和目录名称。

## 五、三类文件及其用途

| 位置 | 用途 | 是否在此修改 |
|---|---|---|
| `D:\campus-lab-work` | 个人项目，D00—D16 的全部实验操作发生在此处 | 是 |
| `教学资源/逐步开发代码/Dxx...` | 每一步完成状态，也是复制来源和完整恢复包 | 否 |
| `教学资源/版本终点核对包/dev-v...` | 七个正式版本的冻结终点 | 否 |

发生错误时，先停止程序，并根据相应实验的恢复说明处理。需要整体恢复时，应先备份个人数据库 `instance/campus_lab.db`，再使用对应 D 文件夹核对受控文件；不要修改课程资源目录中的原始文件。

## 六、正式版本验收基准

| 正式版本 | 对应检查点 | 自动测试基准 |
|---|---:|---:|
| `dev-v0.1` | D03 | 6 passed |
| `dev-v0.2` | D05 | 10 passed |
| `dev-v0.3` | D07 | 14 passed |
| `dev-v0.4` | D10 | 18 passed |
| `dev-v0.5` | D12 | 22 passed |
| `dev-v0.6` | D14 | 28 passed |
| `dev-v1.0` | D16 | 34 passed |

中间检查点也有相应测试，具体数量以各实验为准。只有文件状态、页面结果、业务数据和自动测试同时符合要求，才能进入下一步。

## 七、学习记录要求

每个 D 步骤结束后，应能回答四个问题：

1. 本步复制、替换或删除了哪些文件？
2. 这些文件分别承担什么职责？
3. 本步增加了哪一项可以观察或操作的系统能力？
4. 使用什么页面结果、数据状态或测试结果证明本步已经完成？

能够完成操作但不能说明以上内容，说明尚未真正理解本步；应回看“任务说明”和“实验总结”，再进入下一检查点。
