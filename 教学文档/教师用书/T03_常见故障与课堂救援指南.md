# T03 常见故障与课堂救援指南

## 1. 救援目标和基本原则

课堂救援的目标不是替学生把功能做完，而是尽快判断问题属于哪一层，让学生回到本节规定的成功起点，继续完成同一学习任务。

始终遵守：

1. 先停止继续复制或让AI继续修改。
2. 先记录完整错误、当前路径、版本和工作区状态。
3. 一次只处理第一个失败，不同时尝试五种办法。
4. 先保留可恢复副本，再覆盖或重建。
5. 只处理当前项目中的准确文件，不删除整个目录、用户主目录或磁盘根目录。
6. 不使用`git reset --hard`、`git clean -fd`或不明来源的“一键修复”命令。
7. 恢复代码后仍要由学生本人运行、测试、记录和解释。

## 2. 90秒分层诊断

让学生停止服务器，在项目根目录依次执行：

```powershell
Get-Location
Get-ChildItem -Force
git status --short
git log -1 --oneline --decorate
Test-Path .\.venv\Scripts\python.exe
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m pytest -x -q
```

不要先问“你刚才大概做了什么”，先看可复查证据。按第一条异常进入对应分支：

```text
当前路径或文件不对
└─ 进入第4节：路径与起点

.venv或模块不对
└─ 进入第5节：Python与依赖

程序立即退出、网页打不开、端口冲突
└─ 进入第6节：启动、服务器与浏览器

SyntaxError、IndentationError、TemplateNotFound、BuildError
└─ 进入第7节：源码、路由与模板

sqlite3或sqlalchemy错误、数据数量异常
└─ 进入第8节：SQLite与版本演进

登录循环、403、所有POST变400
└─ 进入第9节：会话、权限与CSRF

pytest收集数或断言失败
└─ 进入第10节：测试

标签、提交、工作区混乱
└─ 进入第11节：Git

AI修改范围失控或反复引入新错
└─ 进入第13节：AI项目
```

## 3. 先保存一张故障单

学生在记录册或临时文本中填写：

| 字段 | 必须记录的内容 |
| --- | --- |
| 时间和课时 | 例如第15课时，10:35 |
| 当前目标 | 例如V0.4合法预约应保存 |
| 当前目录 | `Get-Location`完整输出 |
| 当前版本 | `git log -1 --oneline --decorate` |
| 执行命令 | 一字不漏 |
| 第一个错误 | 从错误类型到最后一行完整复制 |
| 预期结果 | 应看到的页面、状态码、数量或测试数 |
| 已做修改 | 文件名和动作，不写“改了一些代码” |
| 处理结果 | 修复、恢复终点、暂缓及其证据 |

截图可辅助，但可复制的错误文字更适合搜索、比较和交给AI分析。

## 4. 路径、文件和版本起点错误

### 4.1 命令提示“找不到文件”

执行：

```powershell
Get-Location
Get-ChildItem -Force
Test-Path .\app.py
Test-Path .\.venv\Scripts\python.exe
```

项目根目录应同时看到`app.py`、`requirements.txt`、`templates`、`static`、`tests`和`.venv`。如果只看到课程资料目录或上一级文件夹，用`Set-Location`进入自己的项目，不复制第二份代码来掩盖路径问题。

### 4.2 路径中有空格或中文

所有PowerShell路径使用引号或`-LiteralPath`：

```powershell
Set-Location -LiteralPath "D:\student work\校园项目"
Get-Content -LiteralPath ".\templates\base.html" -Encoding UTF8
```

本课程代码已验证可在中文路径运行。出现问题时不要先把中文归因成根因，应先检查当前目录、文件是否完整和命令是否使用引号。

### 4.3 在错误上级目录执行了`git init`

立即停止，不执行删除`.git`的命令。先用：

```powershell
git rev-parse --show-toplevel
Get-Location
git status --short
```

若Git根目录不是学生项目，由教师确认后新建一个准确项目目录，把应有的项目文件复制进去再初始化。错误上级仓库是否保留或处理由教师单独决定，课堂中不要递归删除未知`.git`目录。

### 4.4 当前并非讲义规定标签

```powershell
git log -1 --oneline --decorate
git tag --points-at HEAD
git status --short
```

有未提交修改时先保存：

```powershell
git stash push --include-untracked -m "before classroom start-point rescue"
```

然后查看最近成功标签，不直接硬重置。需要恢复某个版本时，优先按第12节使用对应终点包或新建演示副本。

## 5. Python、虚拟环境和依赖

### 5.1 `py`或`python`无法识别

```powershell
Get-Command py -ErrorAction SilentlyContinue
Get-Command python -ErrorAction SilentlyContinue
where.exe py
where.exe python
```

两者都找不到，说明Python未安装或没有加入启动器/PATH。安装Python 3.11后重新打开PowerShell；不要用Microsoft Store的临时跳转代替课堂统一解释器。

### 5.2 `.venv`不存在

在确认当前目录正确后运行：

```powershell
.\初始化开发环境.bat
Test-Path .\.venv\Scripts\python.exe
```

若双击没有反应，必须在PowerShell中运行脚本以保留错误文字，见第6.1节。

### 5.3 `ModuleNotFoundError: No module named 'flask'`或`flask_sqlalchemy`

先检查实际使用的解释器：

```powershell
.\.venv\Scripts\python.exe -c "import sys; print(sys.executable)"
.\.venv\Scripts\python.exe -m pip show Flask Flask-SQLAlchemy pytest
```

使用裸`python app.py`可能调用全局Python。统一改用：

```powershell
.\.venv\Scripts\python.exe app.py
```

缺库时在虚拟环境内安装锁定依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

### 5.4 依赖安装失败

先记录完整错误，再区分：

| 现象 | 优先检查 |
| --- | --- |
| 域名解析、连接超时 | 校园网络、代理或临时断网 |
| 证书错误 | 系统时间、校园HTTPS代理；不要随意关闭证书校验 |
| Permission denied | 是否误装到全局、杀毒软件是否锁定文件 |
| No matching distribution | Python版本或系统架构是否符合要求 |

教师可在开课前有网络的Windows/Python 3.11环境准备离线包：

```powershell
py -3.11 -m pip download -r requirements.txt -d wheelhouse
```

课堂离线安装：

```powershell
.\.venv\Scripts\python.exe -m pip install --no-index --find-links .\wheelhouse -r requirements.txt
```

只有教师确实准备并分发了匹配的`wheelhouse`时才使用第二条命令。

### 5.5 版本不符合规定

```powershell
.\.venv\Scripts\python.exe -c "from importlib.metadata import version; print(version('Flask')); print(version('Flask-SQLAlchemy')); print(version('pytest'))"
```

手工最终版本和AI起点应为3.1.3、3.1.1、9.1.1。不要使用已弃用的包`__version__`属性来制造无关警告。

## 6. 双击无反应、服务器和浏览器

### 6.1 双击`启动系统.bat`没有反应

这是课堂最先要把“无反应”变成可见错误的场景。不要连续双击，执行：

```powershell
Get-Location
Get-ChildItem -Filter "*.bat"
& ".\启动系统.bat"
```

V0.1的脚本名称是`启动dev-v0.1.bat`，应执行准确文件名。观察窗口中的第一条错误：

- 提示虚拟环境缺失：先运行初始化脚本。
- 提示找不到`app.py`：脚本不在项目根目录或文件未复制完整。
- 提示地址已使用：进入第6.3节。
- 出现Python Traceback：按错误类型进入源码或数据库章节。
- 服务器已经启动但浏览器没打开：手工访问`http://127.0.0.1:5000`。

当前冻结脚本末尾有`pause`，错误窗口应停留。若学生使用的是自行修改脚本，先与版本终点包比较，不猜测隐藏逻辑。

### 6.2 怎样判断服务器真的启动

终端应持续显示类似：

```text
Running on http://127.0.0.1:5000
Press CTRL+C to quit
```

该终端不会立即回到提示符。浏览器能访问首页，终端随后出现GET和状态码。按`Ctrl+C`才是正常停止。

### 6.3 `Address already in use`或5000端口被占用

```powershell
Get-NetTCPConnection -LocalPort 5000 -State Listen -ErrorAction SilentlyContinue
```

若有结果，先检查是否是学生刚才启动但忘记关闭的服务器。回到原终端按`Ctrl+C`。不要直接结束不认识的系统进程。

V1.0可以临时换端口：

```powershell
$env:CAMPUS_LAB_PORT = "5050"
.\.venv\Scripts\python.exe app.py
```

打开`http://127.0.0.1:5050`。V0.1—V0.6的源码固定5000，应先关闭占用者，不临时改冻结代码。

### 6.4 终端启动成功但浏览器拒绝连接

检查：

```powershell
Test-NetConnection 127.0.0.1 -Port 5000
```

确认浏览器地址是`http`而不是`https`，端口与终端一致。代理软件不应代理本地`127.0.0.1`。若终端已回到提示符，说明服务器其实已经退出，应向上找Traceback。

### 6.5 页面仍是旧内容

先按`Ctrl+F5`强制刷新。V1.0使用`debug=False`，代码改变后必须停止并重新启动；不要不断复制同一文件。再查看页面顶部版本是否与当前`VERSION`一致。

### 6.6 本地服务器出现防火墙提示

系统只绑定`127.0.0.1`，本机浏览不需要向公网开放端口。按学校安全要求处理，不为了课堂演示关闭整个防火墙。

## 7. Python源码、路由、模板和静态文件

### 7.1 `SyntaxError`或`IndentationError`

按当前版本已有文件检查：V0.1只检查`app.py`，V0.2—V0.5检查`app.py models.py`，V0.6以后检查三个文件。例如V0.6执行：

```powershell
.\.venv\Scripts\python.exe -m py_compile app.py models.py validators.py
```

以错误给出的第一个文件和行号为中心，对照完整附录或终点包。常见原因：把Markdown的代码围栏一起复制、中文引号替代英文引号、丢失右括号、Tab与空格混用、只复制函数中间一段。

恢复时整体复制该版本的完整文件，不在错误片段上反复补括号。

### 7.2 `TemplateNotFound`

```powershell
Get-ChildItem -LiteralPath .\templates -Recurse
```

核对报错中的准确名称、单复数、下划线和子目录。例如V0.6错误页必须在`templates\errors\404.html`，V1.0版本页是`templates\version.html`。

### 7.3 `BuildError`或`url_for`找不到端点

端点默认是路由函数名。分别查模板调用和Python函数：

```powershell
Select-String -Path .\templates\*.html -Pattern "url_for"
Select-String -LiteralPath .\app.py -Pattern "^    def "
```

确认`url_for('admin_labs')`对应`def admin_labs()`，不是仅仅存在相似URL。优先用对应终点的完整模板和完整`app.py`恢复。

### 7.4 `UndefinedError`或页面变量为空

核对三个名字是否一致：路由传入参数、模板读取变量、模型属性。例如路由传`time_slots=future_slots`，模板必须读`time_slots`。不要通过在模板中删除变量来掩盖后端遗漏。

### 7.5 页面没有样式

打开浏览器开发者工具的Network，刷新后检查`style.css`是否200。再核对：

```powershell
Test-Path .\static\style.css
Select-String -LiteralPath .\templates\base.html -Pattern "style.css"
```

CSS在`static`而不是`templates`。页面内容正常但样式404通常不是Python或数据库错误。

### 7.6 修改了源码却没有任何差异

```powershell
git status --short
git diff -- app.py
```

若没有输出，常见原因是编辑了课程终点包、另一个同名目录或编辑器未保存。用编辑器标题栏完整路径与`Get-Location`核对。

## 8. SQLite、旧数据和版本演进

### 8.1 `no such table`

先完全停止服务器，再从项目根目录运行应用一次。数据库会在应用实例目录中创建。确认模型已经导入并在`db.create_all()`之前可见；不要新建空白`.db`文件。

### 8.2 `no such column: bookings.review_comment`

这是V0.4旧数据库升级到V0.5时的典型现象。检查V0.5完整`app.py`是否包含并调用`upgrade_database_schema()`，模型是否为V0.5。完全重启后再运行S10列检查命令。

### 8.3 数据数量与讲义不一致

先判断是种子数据还是学生操作数据：

```text
干净V0.2：4间实验室
干净V0.3：3名演示用户
干净V0.4及以后：4名演示用户、16个时段、0条预约
学生提交后：预约数量和状态会变化
```

种子函数只在相关表为空时写入。已有个人数据库不会每次启动归零，这是正常持久化，不是测试失败。

### 8.4 需要一个干净数据库做验收

优先在V1.0用独立配置，不碰原数据：

```powershell
$env:CAMPUS_LAB_DATABASE_URL = "sqlite:///acceptance-rescue.db"
.\.venv\Scripts\python.exe app.py
```

若该文件也使用过，换一个新文件名。完成后关闭当前PowerShell，或执行：

```powershell
Remove-Item Env:CAMPUS_LAB_DATABASE_URL
```

### 8.5 早期版本必须重建旧数据库

只对当前项目中已经确认的准确数据库执行可恢复改名：

```powershell
Get-ChildItem -LiteralPath .\instance -Force
Move-Item -LiteralPath .\instance\campus_lab.db -Destination .\instance\campus_lab.before-rebuild.db
```

重新启动生成新库。不要执行递归删除`instance`，备份文件保留到本版通过。

### 8.6 `database is locked`

停止所有指向同一项目的服务器、数据库查看器和测试进程，再试。若项目在云盘同步目录，复制到本地短路径后运行；不要同时在两个程序中写同一个SQLite文件。

## 9. 登录、Session、权限和CSRF

### 9.1 正确账号仍登录失败

先确认版本和账号：V0.3只有`20260001`、`T1001`、`A001`；第二名学生`20260018`从V0.4出现。统一密码是`123456`。

旧数据库若在账号种子完成前生成，启动时的增量种子应补齐缺失账号。仍失败时检查`User.check_password()`和登录路由，不直接把密码改成明文比较。

### 9.2 访问登录页却仍回到当前工作台

这是正确行为：已登录访问`/login`会重定向当前工作台。切换角色必须先单击退出，不能通过再次打开登录页覆盖会话。

### 9.3 预期页面却得到302

未登录访问受保护路由会转到登录页。查看响应最终地址和当前登录用户。自动测试若不跟随重定向，302本身可能正是预期。

### 9.4 预期操作却得到403

先对照权限表和当前账号。错误角色得到403是功能证据，不要为了“打开页面”删除`@role_required`。若正确角色也403，再检查数据库中的`role`值、Session恢复和装饰器参数。

### 9.5 升级V0.6后所有POST都返回400

列出所有令牌字段：

```powershell
Get-ChildItem -LiteralPath .\templates -Recurse -Filter "*.html" | Select-String -Pattern '_csrf_token'
```

V0.6应至少覆盖登录、退出、预约、取消和审批5个POST表单；V1.0还包括每间实验室的管理员操作。检查`app.py`上下文处理器和`before_request`是否完整。

不要删除服务器端保护。旧V0.5测试也必须整体换成V0.6版，通过`post_with_csrf()`提交合法请求。

### 9.6 偶尔出现“表单已过期”

刷新当前表单再提交。若服务器刚重启、密钥改变或浏览器保留旧Session，关闭站点标签并清除`127.0.0.1`站点Cookie。不要手工把固定令牌写进模板。

### 9.7 管理员不能停用实验室

若400页面提示存在待审批或已通过预约，这是REQ-07正确工作。先查相关预约，完成驳回或由学生取消；不能直接删掉冲突查询。

## 10. pytest收集、失败和数据隔离

### 10.1 `collected 0 items`

确认位于项目根目录，测试文件在`tests`，名称以`test_`开头：

```powershell
Get-Location
Get-ChildItem -LiteralPath .\tests
.\.venv\Scripts\python.exe -m pytest --collect-only -q
```

### 10.2 测试数不符合版本

| 版本 | 正确测试数 | 首先检查 |
| --- | ---: | --- |
| V0.1 | 6 | `tests/test_app.py`是否为A06版 |
| V0.2 | 10 | 数据查询与详情测试是否完整 |
| V0.3 | 14 | 登录/角色测试是否完整 |
| V0.4 | 18 | 预约/所有权/取消测试是否完整 |
| V0.5 | 22 | 审批和历史测试是否完整 |
| V0.6 | 28 | `test_validators.py`和CSRF/错误页测试 |
| V1.0 | 34 | `conftest.py`、管理员5类测试和端到端1项 |

数量多1时检查是否保留S11的临时边界测试；少1时用`--collect-only`找缺失名字。不要随意更改参数化测试只为凑数。

### 10.3 只看第一个失败

```powershell
.\.venv\Scripts\python.exe -m pytest -x -vv
```

记录测试完整名、失败断言的预期/实际和第一个项目源码位置。先运行单项：

```powershell
.\.venv\Scripts\python.exe -m pytest tests\test_app.py::test_home_page_is_available -q
```

根据实际失败名替换示例。单项通过后必须再运行全部回归。

### 10.4 `fixture 'app' not found`

V1.0检查`tests\conftest.py`是否存在且为20行完整文件。V0.1—V0.6的fixture在各自`test_app.py`中，不要混用最终版测试结构。

### 10.5 测试运行后手工数据改变

正确测试通过`tmp_path`和`test_config`使用临时SQLite。检查fixture中的`SQLALCHEMY_DATABASE_URI`，不要为了方便指向`instance\campus_lab.db`。

### 10.6 测试导入了错误项目

```powershell
.\.venv\Scripts\python.exe -c "import app; print(app.__file__)"
```

输出必须位于当前学生项目。如果指向另一个目录，检查当前路径、同名模块和编辑器终端是否仍停在旧项目。

## 11. Git提交、标签和工作区

### 11.1 `Author identity unknown`

只为当前学生仓库设置身份，避免误改所有课程环境：

```powershell
git config user.name "学生姓名"
git config user.email "学号@example.invalid"
git config --local --list
```

再重新提交。

### 11.2 `nothing to commit`

```powershell
git status --short
git diff
git log -1 --oneline
```

可能原因：文件未保存、编辑了另一个目录、相同内容已经提交，或新文件被错误忽略。不要为了产生提交随便改空格。

### 11.3 工作区有不明修改，不能进入下一版

先看清内容：

```powershell
git status --short
git diff --stat
git diff
```

需要保留但暂时撤出时：

```powershell
git stash push --include-untracked -m "before next version rescue"
git stash list
```

stash是可恢复保存，不是通过测试的版本标签。

### 11.4 `tag already exists`

先判断旧标签是否正确：

```powershell
git show --no-patch --oneline dev-v0.6
git log -1 --oneline
```

若旧标签错误，先为其提交保留备份名称，再删除错误标签并在正确提交重建：

```powershell
git tag dev-v0.6-mistake-backup dev-v0.6
git tag -d dev-v0.6
git tag -a dev-v0.6 -m "Complete development version 0.6"
```

只有教师确认目标版本和提交后执行。备份标签暂时保留，评分结束再决定是否清理。

### 11.5 `.venv`、数据库或缓存被跟踪

```powershell
git ls-files | Select-String -Pattern "\.venv|__pycache__|\.pytest_cache|instance|\.db$"
```

先确认`.gitignore`准确，再由教师针对显示出的精确路径执行“停止跟踪但保留本地文件”。不要使用广泛匹配删除目录，也不要把虚拟环境上传作为解决依赖的方法。

### 11.6 查看旧标签但不破坏当前工作区

优先只读：

```powershell
git show dev-v0.4:VERSION
git diff --stat dev-v0.3 dev-v0.4
git show dev-v0.4:app.py | Select-String -Pattern "def reserve"
```

课堂抽查不必反复`checkout`旧标签。确需运行旧版本时，教师使用独立终点包或临时工作树，不在学生有未提交内容的目录切换。

## 12. 按版本快速恢复

### 12.1 恢复前的统一动作

确认学生位于自己的项目根目录，先保存所有当前变化：

```powershell
git status --short
git stash push --include-untracked -m "before teacher endpoint rescue"
git status --short
```

从对应`教学资源\版本终点核对包\dev-vX.X`复制终点文件。复制终点包是恢复代码，不会自动证明学生理解；恢复后必须完成该版测试、手工核心场景和记录。

### 12.2 七张恢复卡

| 恢复到 | 必须看到 | 关键特殊动作 |
| --- | --- | --- |

| V0.2 | 15文件、10 passed | 若静态数据仍出现，核对`models.py`和数据库来源 |

```powershell
git rm -- .\templates\reservation_form.html
```

它仍可从V0.3提交恢复。除此之外，不根据“看起来没用”自行删除文件。

### 12.3 恢复后的统一门禁

```powershell
.\.venv\Scripts\python.exe -m py_compile app.py
.\.venv\Scripts\python.exe -m pytest -q
git status --short
```

再执行对应S06—S12中的终点文件比较。只有全部PASS，才提交和建立当前标签。

### 12.4 不复制`.git`和`.venv`

终点核对包本身不含个人Git历史和虚拟环境。恢复时只覆盖受控源码，保留学生自己的`.git`、`.venv`和已经备份的数据；不要把教师项目根目录整体套进学生目录。

## 13. AI项目的专门救援

### 13.1 AI一次输出过多或有省略号

拒绝落地。让AI只列当前版本变更文件，再一次输出1—3个完整文件。确认没有`...`、`TODO`、“此处省略”和未定义函数后再复制。

### 13.2 AI擅自更换技术栈

重新发送S13工作约定，明确只允许Flask、Jinja2、Flask-SQLAlchemy、SQLite和pytest。不要因为AI建议而临时安装Vue、Node、MySQL或新框架。

### 13.3 AI声称已运行成功

把声明标为“未验证”。学生必须执行AI给出的命令，并把真实输出填入记录册。无法给出本机输出时，不把该轮标记为通过。

### 13.4 修一个错又出现多个新错

```powershell
.\.venv\Scripts\python.exe -m pytest -x -vv
git diff --stat
```

只把第一个失败、预期、实际和最相关完整文件交给AI。要求最小修改，不允许“重构整个项目”。若范围继续扩大，保存尝试：

```powershell
git stash push --include-untracked -m "AI repair exceeded scope"
```

回到最近成功标签，把任务缩小成一个文件或一个测试。

### 13.5 AI删除测试或放宽规则来获得通过

立即拒绝。验收标准来自学生确认的AI-REQ，不允许AI单方面修改。恢复测试后修实现；确需改需求，必须记录变更原因并由教师确认。

### 13.6 AI生成代码看不懂

停止加功能，让AI只解释：输入、主要分支、数据库读写、返回值、错误路径。学生在当前文件逐项定位，并用一个测试验证解释。仍不能说明时，本轮不提交。

### 13.7 AI项目进度落后

按顺序缩减，不取消核心过程：

```text
自选题改为默认社团活动题
→ 删除AI-REQ-07/08，只保留6项
→ 页面降到4个，状态降到3种
→ 停止界面美化
→ 使用最近成功标签重新开始当前小版
```

不能缩减：两个角色的服务器端权限、一条核心状态流程、SQLite、至少10项测试、一个缺陷闭环和Git五个基线。
