# S01 开发环境配置与常用工具

## 1. 本章在整个项目中的位置

上一章先看到了最终系统和七个版本的全貌。本章不开发业务功能，只完成一件基础工作：

> 让每位同学的电脑都具备相同、可检查、可恢复的软件运行环境。

软件在教师电脑上能够运行，不等于在所有同学电脑上都能运行。Python版本不同、依赖版本不同、当前目录不对，都可能让完全相同的代码产生不同结果。因此，环境配置本身就是软件开发的一部分。

完成本章后，你应当能够：

- 区分Python、Python包、虚拟环境和项目文件夹。
- 确认电脑上的Python版本是否满足课程要求。
- 在项目目录中创建独立的`.venv`虚拟环境。
- 按`requirements.txt`安装完全一致的依赖版本。
- 识别项目使用的Python解释器。
- 启动系统、访问网页并正确停止服务器。
- 根据错误现象判断问题出在路径、解释器、依赖还是端口。

## 3. 先理解四个容易混淆的概念

### 3.1 Python解释器

Python解释器是执行`.py`文件的程序。例如：

```text
C:\Users\你的用户名\AppData\Local\Programs\Python\Python311\python.exe
```

同一台电脑可能同时安装多个Python版本，所以“已经安装Python”还不够，还要确认项目实际使用的是哪一个解释器。

### 3.2 Python包

Flask、Flask-SQLAlchemy和pytest不是项目自己实现的功能，而是项目依赖的第三方包：

- Flask负责接收浏览器请求并返回页面。
- Flask-SQLAlchemy负责让Python程序读写SQLite数据库。
- pytest负责执行自动测试。

### 3.3 虚拟环境

虚拟环境是项目自己的Python运行空间。本项目把它放在项目根目录下的`.venv`文件夹中。

```text
电脑上的Python 3.11
        ↓ 创建
项目自己的.venv
        ↓ 安装
Flask 3.1.3、Flask-SQLAlchemy 3.1.1、pytest 9.1.1
```

这样做有两个直接好处：

1. 课程项目不会修改全局Python环境。
2. 另一个项目需要不同版本的包时，不会与本项目冲突。

### 3.4 项目根目录

能够直接看到`app.py`、`requirements.txt`和`启动系统.bat`的文件夹，才是本项目的根目录。

```text
campus-lab-development/
├─ app.py
├─ requirements.txt
├─ 初始化开发环境.bat
├─ 启动系统.bat
├─ 运行测试.bat
├─ templates/
├─ static/
└─ tests/
```

终端所在目录不正确，是初学者最常见的问题之一。

## 4. 安装并检查Python 3.11

### 4.1 安装时必须注意的选项

如果电脑尚未安装Python 3.11，请使用课程提供的安装程序，或从Python官方网站取得64位安装程序。安装界面中应勾选：

```text

```

该选项让Windows终端能够找到Python。安装完成后，关闭原有终端，再打开一个新终端。

### 4.2 打开终端

可以采用以下任一方式：

- 在开始菜单中搜索“PowerShell”。
- 在Visual Studio Code中选择“终端 → 新建终端”。
- 在项目文件夹空白处按住Shift并单击鼠标右键，再选择在终端中打开。

本讲义的手工命令以PowerShell为准。

### 4.3 检查版本

依次尝试：

```powershell
py -3.11 --version
```

预期看到类似结果：

```text
Python 3.11.9
```

如果Windows没有`py`命令，再尝试：

```powershell
python --version
```

只要显示`Python 3.11.x`即可继续。最后一位修订号不要求完全相同。

如果两个命令都提示“无法识别”，说明Python尚未正确安装，或安装后没有重新打开终端。

## 5. 准备课程项目文件夹

### 5.1 解压，而不是在压缩包内直接打开

把教师提供的课程项目压缩包完整解压到本地磁盘。建议使用简单、固定的目录，例如：

```text
D:\software-course\campus-lab-development
```

不要直接在压缩软件的预览窗口中双击脚本。预览窗口通常只临时解压单个文件，会导致脚本找不到`requirements.txt`、`templates`或`static`。

路径中出现中文和空格并不一定会失败，但较短的英文路径更便于输入命令和排查错误。

### 5.2 检查是否多套了一层文件夹

正确情况：

```text
D:\software-course\campus-lab-development\app.py
```

常见错误情况：

```text
D:\software-course\campus-lab-development\campus-lab-development\app.py
```

如果多套一层，应进入真正包含`app.py`的内层文件夹操作。

## 6. 方法A：双击脚本完成环境初始化

这是课堂推荐方法。

### 6.1 执行步骤

1. 打开项目根目录。
2. 双击`初始化开发环境.bat`。
3. 等待依赖下载和安装，不要提前关闭窗口。
4. 看到下面一行后按任意键关闭窗口：

```text
Development environment is ready.
```

### 6.2 这个脚本实际做了什么

项目中的脚本完整内容如下：

```bat
@echo off
setlocal
cd /d "%~dp0"

if not exist ".venv\Scripts\python.exe" (
    py -3.11 -m venv .venv 2>nul
    if errorlevel 1 python -m venv .venv
)

if not exist ".venv\Scripts\python.exe" (
    echo Failed to create the virtual environment.
    pause
    exit /b 1
)

set PIP_DISABLE_PIP_VERSION_CHECK=1
".venv\Scripts\python.exe" -m pip install -r requirements.txt
if errorlevel 1 (
    echo Dependency installation failed.
    pause
    exit /b 1
)

echo Development environment is ready.
pause
```

关键语句的含义：

- `cd /d "%~dp0"`：不管从哪里双击，都先进入脚本所在的项目目录。
- `py -3.11 -m venv .venv`：使用Python 3.11创建项目虚拟环境。
- `python -m venv .venv`：电脑没有`py`命令时使用备用方式。
- `".venv\Scripts\python.exe"`：明确使用项目自己的解释器。
- `-m pip install -r requirements.txt`：读取依赖清单并安装指定版本。
- `errorlevel`：前一步失败时显示错误并停止，避免把失败误认为成功。

脚本中的提示采用英文，是为了减少不同Windows终端编码导致的乱码；不影响中文页面。

### 6.3 成功后的可见结果

项目根目录中会出现：

```text
.venv/
├─ Scripts/
│  ├─ python.exe
│  └─ pip.exe
└─ Lib/
   └─ site-packages/
```

`.venv`只属于当前项目。不要把它复制给其他同学，也不要提交到Git仓库；每台电脑都应根据`requirements.txt`重新创建。

## 7. 方法B：用PowerShell手工完成初始化

双击脚本失败时，不要反复盲目双击。手工执行能够看清失败发生在哪一步。

下面假设项目位于`D:\software-course\campus-lab-development`。如果你的路径不同，应替换为自己的实际路径。

### 7.1 进入项目目录

```powershell
Set-Location "D:\software-course\campus-lab-development"
```

检查当前位置：

```powershell
Get-Location
Get-ChildItem
```

输出列表中必须能够看到`app.py`和`requirements.txt`。

### 7.2 创建虚拟环境

```powershell
py -3.11 -m venv .venv
```

如果系统只有`python`命令，则执行：

```powershell
python -m venv .venv
```

创建成功后检查解释器：

```powershell
Test-Path .\.venv\Scripts\python.exe
```

预期结果：

```text
True
```

### 7.3 安装锁定版本的依赖

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

这里故意不使用单独的`pip`命令。`python.exe -m pip`可以明确保证：依赖安装到了这个Python解释器所属的虚拟环境中。

### 7.4 依赖清单的准确内容

本项目`requirements.txt`为：

```text
Flask==3.1.3
Flask-SQLAlchemy==3.1.1
pytest==9.1.1
```

`==`表示锁定具体版本。课程中每个人使用相同版本，可以减少“同一份代码在不同电脑上表现不同”的问题。

## 8. 检查环境是否真的可用

“安装过程没有报错”只是第一层检查，还要让解释器真正导入这些包。

### 8.1 检查项目解释器版本

```powershell
.\.venv\Scripts\python.exe --version
```

预期显示`Python 3.11.x`。

### 8.2 检查三个依赖版本

复制并执行下面这一整行：

```powershell
.\.venv\Scripts\python.exe -c "from importlib.metadata import version; print('Flask', version('Flask')); print('Flask-SQLAlchemy', version('Flask-SQLAlchemy')); print('pytest', version('pytest'))"
```

预期结果：

```text
Flask 3.1.3
Flask-SQLAlchemy 3.1.1
pytest 9.1.1
```

这一步同时证明了三件事：

1. 项目解释器能够启动。
2. 三个包已经安装到该解释器中。
3. 安装的版本与课程基线一致。

## 10. 启动并访问系统

### 10.1 双击启动

在项目根目录双击：

```text
启动系统.bat
```

脚本完整内容如下：

```bat
@echo off
setlocal
cd /d "%~dp0"

if not exist ".venv\Scripts\python.exe" (
    echo Virtual environment is missing.
    echo Run the setup script first.
    pause
    exit /b 1
)

start "" powershell -NoProfile -WindowStyle Hidden -Command "Start-Sleep -Milliseconds 1200; Start-Process 'http://127.0.0.1:5000'"
".venv\Scripts\python.exe" app.py
pause
```

脚本先检查`.venv`，再运行`app.py`，并在短暂等待后打开浏览器。

### 10.2 成功时应看到什么

命令窗口中应出现类似信息：

```text
* Running on http://127.0.0.1:5000
```

浏览器会自动打开；如果没有自动打开，请手工输入：

```text
http://127.0.0.1:5000/
```

能够看到“校园实验室预约与审批系统”首页，就说明浏览器、Flask程序和本地端口已经连通。

### 10.3 正确停止服务器

回到正在运行程序的命令窗口，按：

```text
Ctrl+C
```

关闭窗口也能终止程序，但`Ctrl+C`可以明确告诉服务器正常停止。服务器停止后刷新浏览器，应显示无法访问该地址；这不是系统损坏，而是本地服务已经结束。

## 11. 认识三个课程脚本

| 脚本 | 何时使用 | 是否会修改业务代码 |
| --- | --- | --- |

```bat
if not exist ".venv\Scripts\python.exe" (
    echo Virtual environment is missing.
    echo Run the setup script first.
    pause
    exit /b 1
)

".venv\Scripts\python.exe" -m pytest -q
pause
```

本章只要求认识测试入口。测试用例的设计、执行和结果分析将在V0.6阶段集中学习。

## 12. 常见问题与定位方法

### 问题1：双击初始化脚本后窗口立即关闭

不要继续猜测。打开PowerShell，进入项目根目录，按第7节逐条执行。最后一条成功命令之后的第一条错误信息最有价值。

### 问题2：提示找不到`py`或`python`

可能原因：

- Python尚未安装。
- 安装时没有加入PATH。
- Python刚安装，但当前终端还没有重新打开。

先重新打开终端并执行`py -3.11 --version`。仍然失败时，重新运行Python安装程序并启用PATH选项。

### 问题3：提示找不到`requirements.txt`

当前目录不在项目根目录。执行：

```powershell
Get-Location
Get-ChildItem
```

进入能够直接看到`requirements.txt`的目录后再安装。

### 问题4：依赖下载超时或失败

先确认网络可用，再原样重新执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

安装命令可以重复执行。已经正确安装的版本会被保留，不会破坏环境。

### 问题5：提示`No module named 'flask'`

通常是运行程序的解释器和安装依赖的解释器不是同一个。不要使用不确定的`python app.py`，改用：

```powershell
.\.venv\Scripts\python.exe app.py
```

### 问题6：提示端口5000已被占用

这通常表示另一个项目窗口中的服务器还在运行。找到先前启动系统的窗口并按`Ctrl+C`，然后重新启动。

可用下面的命令查看哪个进程正在监听5000端口：

```powershell
Get-NetTCPConnection -LocalPort 5000 -State Listen
```

不要直接结束一个不了解的进程。先根据`OwningProcess`编号确认它是否是自己刚才启动的Python程序。

### 问题7：浏览器打不开，但窗口没有错误

依次检查：

1. 命令窗口是否仍然打开。
2. 是否出现`Running on http://127.0.0.1:5000`。
3. 浏览器地址是否为`http://127.0.0.1:5000/`，而不是`https`。
4. 是否把`127.0.0.1`理解成本机；同学之间不能通过这个地址互相访问。

### 问题8：`.venv`文件很多，是否需要阅读或提交

不需要。它是工具生成的运行环境，不是本课程要开发的源码。项目的`.gitignore`已经排除：

```text
.venv/
__pycache__/
.pytest_cache/
*.py[cod]
instance/
```

其中`instance/`保存本机运行时数据库，也不作为源代码提交。

## 14. 本章操作练习

### 练习1：找出两个Python

分别执行：

```powershell
Get-Command python -ErrorAction SilentlyContinue
Resolve-Path .\.venv\Scripts\python.exe
```

记录两个路径，说明哪一个属于电脑全局，哪一个属于本项目。

本练习不修改任何文件，无需恢复。

### 练习2：验证当前目录

先进入项目的上一级目录，再执行：

```powershell
Test-Path .\requirements.txt
```

观察`False`。然后回到项目根目录再次执行，观察`True`。

恢复方法：确保练习结束时终端位于包含`app.py`和`requirements.txt`的项目根目录。

### 练习3：验证依赖来自虚拟环境

执行：

```powershell
.\.venv\Scripts\python.exe -c "import sys; print(sys.executable)"
```

输出必须以当前项目的`.venv\Scripts\python.exe`结尾。

本练习不修改任何文件，无需恢复。

### 练习4：完成一次启动—访问—停止

1. 双击`启动系统.bat`。
2. 访问首页。
3. 记录页面标题。
4. 回到命令窗口按`Ctrl+C`。
5. 刷新浏览器，确认服务已经停止。

本练习只可能在`instance/`中生成本地数据库。该目录是运行数据，不影响后续源码；无需手工删除。

### 练习5：根据错误现象选择处理位置

把下面现象分别归入“路径”“解释器”“依赖”或“端口”问题：

1. `requirements.txt`不存在。
2. `No module named 'flask'`。
3. `Address already in use`。
4. 执行`python --version`显示的不是3.11。

本练习不修改任何文件，无需恢复。
