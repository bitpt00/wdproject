# S0到dev-v0.1半自动教学平台使用说明

本平台服务于非计算机专业学生的软件项目开发课程。它把S06中`S0→dev-v0.1`的过程拆为C0—C8九个检查点，让学生不用手写大段代码，也能真实经历“预测—操作—观察—解释—测试—故障—恢复—版本”的闭环。

平台不会替学生填写答案，也不会把“代码已经复制”判定为任务完成。

## 1. 启动

学生电脑只需预先安装Python。首次使用时：

1. 下载或克隆整个课程仓库的`main`分支。
2. 双击项目根目录的`启动教学平台.bat`。
3. 脚本会在项目目录内使用`.venv`；不存在时自动创建并安装`requirements.txt`中的锁定依赖，不修改全局Python包。
4. 浏览器会自动打开`http://127.0.0.1:8000`。若没有自动打开，手工输入该地址。
5. 输入本人学号和姓名。学号只允许英文字母、数字、下划线和短横线。

命令窗口必须在上课期间保持打开。关闭窗口即停止教学平台，但已保存的学习进度不会丢失。

## 2. 学生每一步怎样做

每个检查点都使用同一顺序：

1. 听教师讲解本步解决的问题和关键概念。
2. 阅读思考题，先填写“操作前预测”并保存。
3. 单击“应用准确文件”。C0在创建个人工作区时已经应用。
4. 打开代码观察器或差异页，找出文件放在哪里、哪些行发生变化。
5. 在C2以后单击“启动学生项目”，再亲自在新标签页访问和操作。
6. 回到平台填写“操作后观察”和“原理解释”。
7. 单击“检查文件与行为”，最后完成本步门禁。

C3和C4是准备步骤：文件虽然已经加入，页面仍保持C2纯文字，这是正确结果，不是平台失败。

## 3. C0—C8结果

| 检查点 | 应用后主要结果 | 学生必须理解 |
| --- | --- | --- |
| C0 | 3个S0起点文件和干净Git提交 | 环境基线不是软件功能 |
| C1 | 建立static、templates、tests空目录 | 项目结构按职责组织 |
| C2 | 根地址显示纯文字版本信息 | URL—Flask路由—响应 |
| C3 | 准备布局、首页和CSS，页面不变 | 文件存在不等于程序已使用 |
| C4 | 准备实验室列表模板，页面不变 | 模板需要路由与数据 |
| C5 | 首页、列表、静态预约表单可用 | 路由、模板、内存数据和查询参数 |
| C6 | 加入启动和测试入口，pytest尚无用例 | 工具、入口和用例的区别 |
| C7 | 5项手工验收和6项自动测试 | 预期、实际、断言和参数化 |
| C8 | 故障恢复、13文件核对和Git标签 | 恢复后回归与里程碑证据 |

## 4. 测试和故障操作顺序

C6先运行一次pytest，正确现象是“没有收集到测试”。这用于证明测试入口已经存在，而测试用例尚未加入。

进入C7后：

1. 先在“测试记录”页填写5项用例的前置条件、操作和预期。
2. 启动学生项目，逐项手工操作。
3. 填写实际结果和“通过/不通过”。
4. 应用C7自动测试文件并运行pytest，正确结果为`6 passed`。

C8会暂时移出`templates/index.html`并展示`TemplateNotFound`。学生必须先填写现象和判断依据，平台才恢复准确文件。恢复之后必须重新运行6项测试；恢复之前的旧测试结果不能用于冻结版本。

## 5. 文件保存在哪里

每个学生的项目、状态、日志、备份和证据都位于平台自己的运行目录：

```text
teaching_platform/runtime/
├─ workspaces/学号/     学生从S0逐步形成的项目和独立Git仓库
├─ states/              预测、观察、解释、测试和操作记录
├─ logs/                学生网站运行日志
├─ backups/             受控故障恢复备份
└─ exports/             最终ZIP学习证据包
```

`runtime`内容不会提交到教师课程仓库。平台不会管理用户目录、课程仓库其他文件、其他学号目录、`.git`或`.venv`。

## 6. 教师课堂使用

- 教师主讲概念、过程、真实项目经验和抽查问题，不需要逐台复制代码。
- 学生必须本人点击、查看、运行、测试和解释，教师抽查时可让其指出一个URL对应的路由和模板。
- `/teacher`只显示本机工作区摘要。在“每人自带电脑”的课堂中，它主要用于教师走到学生电脑旁快速检查，并不是联网收作业系统。
- 最终让学生提交ZIP证据包；代码工作区仍保留在本人电脑，可用于现场复核Git提交和标签。

## 7. 教师验收命令

平台已经覆盖PT-01—PT-15和一条完整网页流程。教师更新代码后可重新执行：

```powershell
.\.venv\Scripts\python.exe -m pytest teaching_platform\tests -q
```

正确结果为：

```text
16 passed
```

还应双击`启动教学平台.bat`，确认`http://127.0.0.1:8000/health`返回`status: ok`，首页显示“从 S0 起点，亲手形成 dev-v0.1”。

## 8. 当前范围

当前原型只覆盖`S0→dev-v0.1`，这是为了先验证非计算机专业学生能否真正理解首个开发闭环。V0.2—V1.0尚未接入平台，不应在课堂上声称已经自动化；继续按S07—S12和版本终点核对包实施。下一阶段按T04建设顺序扩展`dev-v0.1→dev-v0.2`。
